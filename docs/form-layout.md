# 表单排版规范

编辑器和运行态共用 `mokelay-components/src/styles/forms.css`，通过已发布的 `mokelay-components/style.css` 加载。只显式使用 `mk-form-*` 的元素参与规范；不使用全局 `input` / `label` 选择器覆盖第三方组件。事件面板的组合样式位于 `src/forms.css`。

## 尺寸与结构

| 项目 | 规范 |
| --- | --- |
| 标签 | 上方，13px / 20px，600 字重；允许换行 |
| 输入框、下拉框、按钮 | 最小高度 40px；窄屏 44px；文本 14px / 20px；圆角 8px |
| 多行输入 | 最小高度 96px，允许垂直调整；JSON 文本可使用等宽字体 |
| 提示与错误 | 控件下方，12px / 18px；长文本自动换行 |
| 标签与控件 | 6px |
| 字段间距 | 16px |
| 分区间距 | 24px |
| 弹窗 | 标准 640px、宽版 960px、画布版 1200px；距视口至少 16px |
| 弹窗滚动 | 页头和页脚不收缩，只有正文滚动；不把浮动操作按钮放到正文上 |

优先使用 `mk-form-field`、`mk-form-label`、`mk-form-control`、`mk-form-help`、`mk-form-error`。复选框/单选框使用 `mk-form-check-row` 和 `mk-form-check`，不能套文本输入框的全宽样式。主操作使用 `mk-form-button--primary`，删除操作使用 `mk-form-button--danger`。

纵向字段组用 `mk-form-stack`，有关联的短字段用 `mk-form-grid`，长字段用 `mk-form-full`。在有确定宽度的表单、弹窗正文或属性栏放置 `mk-form-scope`，通过容器查询在可用宽度变小时折为单列，不以桌面视口宽度推断嵌套面板空间。

弹窗采用 `mk-form-dialog` → `mk-form-dialog-panel` → `mk-form-dialog-header` / `mk-form-dialog-body` / `mk-form-dialog-footer`。Vue Teleport 与字符串创建的原生 dialog 使用相同类。不能在组件内部重新定义这些基础尺寸、颜色和间距；通过共享 `--mk-form-*` 变量维护浅色/深色主题。

## 适用面

- 事件与通用 Block 属性面板，包括 MForm 的字符串模板属性面板。
- Action 图形编辑器的属性栏、变量绑定与变量流程属性栏。
- 表单项、字段规则、工具栏、表格列、字段列表、图表数据、Tabs、布局网格、多语言内容配置。
- 数据源请求/响应配置、导入 API、响应模拟、Processor 参数与预览弹窗。
- API Builder 与 API 编排的属性输入、参数、响应和创建表单。
- 运行态 MForm / MFormItem、文本/选择/多行/上传控件、单选/复选/图片选择；日期范围组件通过自己的适配层接入高度和主题变量。

图形画布、代码/JSON 编辑器内部保留专有布局；周围的属性输入遵循本规范。字段表格保留列结构，由表格容器承接横向滚动。显式 DSL `layout: Horizontal`、`itemWidthMode: compact` 继续生效；窄容器折行，不迁移或重写已有 DSL。

## 事件面板

每个事件使用独立卡片：编号和删除操作在卡片顶部，触发事件占整行；主动作、失败动作、结束动作三个入口等宽，显示各自的动作数量；窄容器改为纵向。执行策略独立折叠，生命周期复选项独占一行。添加操作位于固定页脚。

保持即时写入与关闭语义。展开策略、编辑 Action 不重建事件名称输入；添加/删除事件保留其他策略的展开状态。`events`、`actions`、`onError`、`onFinally` 与执行策略的数据格式不变。

## 验证

`e2e/form-layout.spec.ts` 验证 390 / 768 / 1440px、深色、窄容器、按钮对齐和无横向溢出、页脚可达、展开状态、三个动作链和计数保存。结合 `form-events`、`block-events`、`m-form`、`m-form-item` 现有测试覆盖初始化、保存、重放、提交、字段校验和 DSL 持久化。

### 本次验证记录（2026-11-20）

- 组件库：22 个测试文件、79 项测试通过；组件库构建及类型检查通过。
- 编辑器：生产构建和类型检查通过，`git diff --check` 通过。
- 针对性浏览器用例：事件配置、三个动作链、表单/表单项、报销初始化/自动保存/重试/提交、日期选择和序列化、共享弹窗与 API 属性栏，共 44 项不同用例通过（包含对失败用例的修正后复验）。在 390 / 768 / 1440px、深色英文、桌面窄容器进行尺寸断言并检查实际截图。日期字段的首次数据源变量请求用例仍失败：第一次请求携带空日期；日期选择、清除和序列化通过。未把这一项算作通过。
- 本地 editor / render 均安装了当前组件库构建产物，没有修改依赖版本声明或锁文件。

扩展回归不是全绿：100 项用例首轮 83 项通过、17 项失败。日期选择器没有撑满容器的问题已修复并复验；其余问题涉及首次请求次数、编辑器专用字段组件的运行态预览、Grid 空段落、Tabs 的旧属性/按钮定位，以及未模拟登录的 Processor 用例跳转离开编辑器。旧 API Builder 路由套件另因 `/apis` 返回 404 未继续运行；其创建表单和编排组件已通过独立界面测试。上述其他功能/测试问题没有在这次排版改动中修改。

报销表单用例只使用应用的字段和事件 DSL，显式隔离应用外壳的 `layoutUuid`，并在 MForm 内定位控件，避免把页面导航中的主题选择器当成业务字段。没有改写应用页面的布局配置。
